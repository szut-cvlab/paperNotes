## 摘要

**问题**: 通用 VLM 精确定位是短板——让语言模型直接生成坐标 $[x_1,y_1,x_2,y_2]$ 格式脆弱，多目标下序列更长、更易出错。

**方案**: VLX-Seek 将定位重构为**区域引用**（region reference）：接收可寻址区域 token，定位即输出区域索引。三步流水线：OPN 候选生成 → HFRE 混合区域编码 → LLM 推理。1.0（2026-06-27）确立范式，1.5（2026-07-06）面向具身场景强化（无人机/机器人数据、三档模型规模、显式 None 拒答格式）。

**关键创新/贡献**：
- 区域引用范式：定位纳入 LLM 擅长的选择/引用，输出稳定、易解析、多目标下更短
- HFRE 双路编码：语义对齐 + 高分辨率细节并行，SimpleFP 补多尺度
- 显式 None 输出 + 难负样本训练：目标不存在时明确拒答，压幻觉

**验证**: 1.0-3B COCO 45.3 mAP（vs Gemini 3.1 Pro 41.4）、RefCOCO 平均 88.7、PixMo-Count 85.0；1.5 新增无人机/具身空间/幻觉（FP/GT）评测。

## 01 / VLX-Seek 1.0（2026-06-27）：把"生成坐标"变成"引用区域"

### 1.1 坐标生成为什么脆弱

坐标不是自然语言——LLM 擅长生成词句而非可靠输出精确数值。单框 4 个坐标，多目标变成更长的数字序列；顺序、归一化范围、标点格式、目标数量任一处出错，结果就无法解析或明显偏移。目标越多，生成路径越长，漏检和格式错误概率越高、推理越慢。

### 1.2 区域引用范式

输入侧：模型不再只接收全图视觉 token 和文本 token，还接收一组可寻址区域 token，每个对应一个候选区域，区域索引与区域特征绑定喂给 LLM。输出侧：定位即输出区域索引引用——

```
The <ground>people</ground><object><region2><region10></object> are dancing.
```

文本"people"对应图中 `<region2>` 和 `<region10>`。定位从"生成精确几何数字"变为"语言条件下的候选区域检索"，更契合 LLM 天然擅长的比较、选择、引用与解释能力。四重收益：

1. **更稳定**：输出区域索引而非易错的精确数值
2. **更清晰**：先理解描述 → 匹配区域 → 输出可解析引用
3. **更快速**：多目标下区域索引远短于长坐标序列，解码成本低、推理快
4. **更统一**：检测、REC、区域 captioning、区域 VQA、计数统一在同一区域 token 框架下

与"检测增强型 VLM"（外挂检测头）的本质区别：VLX-Seek 把候选区域作为**新的视觉-语言实体**引入模型——图中的物体获得类似"语言实体"的地位，模型不仅能描述它们，还能引用、比较并对它们推理。

### 1.3 三步推理流水线

**Step 1 候选区域生成（OPN，Omni Proposal Network）**: 检索图中可能含前景的区域，只求"找得全"不做类别判断。OPN 与 VLM 主干解耦——可替换为其他检测器，或直接使用人工指定的 ROI。

**Step 2 区域编码（HFRE，Hybrid Fine-grained Region Encoder）**: 候选框只是几何范围，不包含"框里是什么/与其他区域有何不同/是否匹配描述"。HFRE 从候选框提取区域级视觉特征并投影到 LLM embedding 空间，使区域从"一组坐标"变成"LLM 可读取、比较、引用的视觉表示"。

**Step 3 LLM 基于区域 token 推理**: 模型输入 = 全局图像 token + 文本 token + 编号区域 token，通过区域索引完成定位与回答。

### 1.4 HFRE：语义与细节双路

核心挑战：单一视觉编码器难以同时满足语义对齐与细粒度空间感知。通用 VLM 的原始视觉编码器已与语言模型对齐、擅长全局语义，但通常未针对细粒度检测训练，对小目标、边界、局部纹理、多尺度区域的表征不足；检测导向/高分辨率编码器则相反——对局部细节敏感，但不在 LLM 能直接理解的语义空间中。

HFRE 的解法：**主视觉编码器保留原 VLM 的语义对齐能力**（理解区域"像什么/可能是什么"），**辅助视觉编码器提供高分辨率局部细节**（感知边界、纹理、小目标、区域间差异）；**SimpleFP 模块**为 ViT 式特征补充多尺度表征（单尺度难以同时覆盖大人和手机、杯子、招牌级别的小物体）；按候选框从视觉特征图上提取区域特征，最后由**区域-语言连接器**投影到 LLM embedding 空间。

核心价值：每个区域 token 同时携带高层语义与细粒度空间细节——对普通 VQA，"这是一辆车"可能够用；对开放词汇检测与具身任务，还必须知道"是哪辆车、在图中哪里、边界与邻近物体如何区分"。

### 1.5 两阶段训练

目标是增强细粒度感知的同时尽量不损伤 VLM 原有通用能力，同时规避两个风险：

- **阶段一：区域-语言对齐**——冻结 VLM 主参数，集中训练 HFRE、区域-语言连接器与新增特殊 token，让模型先稳定学会"区域 token 对应视觉区域"
- **阶段二：感知指令微调**——引入检测、REC、区域 captioning、区域推理、计数、OCR 任务。关键不是堆数据，而是同时防两类风险：
  - **灾难性遗忘**（细粒度增强损害通用视觉问答/captioning/常识推理）→ 混入常规 VLM 指令数据
  - **开放词汇拒答能力缺失**（真实场景不仅"找到存在的"，还要"避免找到不存在的"）→ 加入拒绝样本，目标缺席时回答"不存在"而非强行指向某个区域

论文式总结：模型不仅学"如何找到目标"，还学"何时不找"。

### 1.6 基准表现（VLX-Seek-3B）

| 基准 | 得分 | 对比 |
|------|------|------|
| COCO 检测 mAP | 45.3 | Qwen2.5-VL-7B 17.7；Gemini 3.1 Pro 41.4 |
| OVDEval（开放词汇 + 困难负样本） | 43.7 | — |
| RefCOCO 系列平均 | 88.7 | Gemini 3 Pro 84.1；Qwen3-VL-8B 88.2 |
| PixMo-Count | 85.0 | Gemini 2.5 Pro 73.8 |

计数优势来自"先检测引用实例、再聚合"——比凭整体印象估数可靠（仅靠全局语义的模型容易高估/低估目标数量）。

## 02 / VLX-Seek 1.5（2026-07-06）：面向具身场景的三线升级

### 2.1 更强感知

- 扩充无人机视角、监控视角、机器人视角等**具身训练数据**——这些场景暴露了标准网页图像基准覆盖不足的视觉条件：无人机视角的极小目标、密集布局、大尺度变化、倾斜视角；监控/移动摄像头的广角畸变、低分辨率、拥挤画面、运动模糊
- 升级 **Aux Vision Tower** + 更强 VLM backbone，同时改善视觉-语言对齐与纯视觉特征质量，提升区分相似实例、理解复杂指代表达、困难具身环境检测的能力

### 2.2 更快推理

- 模型家族扩展为 **0.6B / 3B / 10B** 三档，覆盖轻量端侧感知到服务器端/机器人基站推理的边云部署形态
- 引入更多 **Linear Attention 层** + 更快 OPN proposal 管线，提升推理效率并降低内存
- 继承区域引用范式：不为每个目标解码冗长坐标字符串，多目标定位与交互式感知的输出路径更短

### 2.3 更少目标幻觉

动机：开放世界具身场景中，幻觉式检测有时比漏检更危险——机器人走向错误物体、无人机追踪不存在的目标、监控误报。

- 训练中加入更多**难负样本拒识数据**
- 改进检测输入输出格式为**显式 None**：此前较隐式的格式中，提示同时询问目标 A 和 B、图中只有 A 时，模型可能只返回 A 并省略 B；1.5 要求返回 A 的结果并**将 B 显式标记为 None**——模型不仅学"如何定位可见目标"，也学"如何明确拒绝不存在的目标"。对真实具身系统，知道请求目标缺失与找到存在目标同样重要

### 2.4 评测体系（六组）

| 组 | 基准 | 说明 |
|----|------|------|
| 表 1-3 | COCO/LVIS/ODinW、RefCOCO 系、PixMo-Count 等 | 通用检测 / REC / 计数 |
| 表 4 | VisDrone、RefDrone | **无人机视角感知** |
| 表 5 | RefSpatial、EmbSpatialBench | 具身空间推理 |
| 表 6 | HumanRef、VisDrone、RefDrone | **目标幻觉**，指标 FP/GT（越低越好） |

对比对象：上一版 VLX-Seek、Rex-Omni、LocateAnything 等检测增强型 VLM 及更大开源/闭源模型。所有表格以图片形式发布，具体数值无法从页面提取。

**幻觉指标定义**：

$$
\text{Object Hallucination} = \frac{\text{FP}}{\text{Number of GT Objects}}
$$

FP 为针对实际不存在的请求目标产生的假阳性检测，用真实目标数归一化；分数越低幻觉越少。

## 04 / 技术谱系与定位

Om AI Lab 此前开源过 OmDet-Turbo、VLM-R1、VLM-FO1（开放词汇检测/区域理解方向），VLX-Seek 是 VLX 系列的最新工作。与同类模型的核心差异：VLX-Seek 不是给 VLM 外挂检测头，而是把候选区域作为"内部视觉-语言实体"参与推理/比较/对话。在 1.5 的对比表中，参照系为 Rex-Omni（坐标 token + GRPO）与 LocateAnything（并行框解码 PBD）。

## 05 / 小结

VLX-Seek 的价值不在"更大更强"，而在用范式重构解决被长期忽视的问题：让 VLM 真正"看清细节"而非只"理解大意"。1.0 确立"区域引用替代坐标生成"并验证了小模型胜大模型的可行性；1.5 把这套范式推向真实具身场景——数据（无人机/监控/机器人视角）、效率（三档规模 + Linear Attention）、可靠性（显式 None + 难负样本）三条线同步收紧。

## 个人评价

**核心价值**: "区域 token 选择"是对"坐标生成"范式的有力挑战。它与 LocateAnything 的并行框解码（PBD）代表两条不同路线：PBD 仍生成坐标但并行化；VLX-Seek 干脆不生成坐标，把定位变成 LLM 擅长的索引选择。对端侧具身场景（低延迟、小模型、可解析输出），这条路线的工程价值很实在。1.0→1.5 两个月的迭代节奏（范式验证→具身强化）也是开源项目运营的范本。

**可借鉴点**:
- **显式 None 输出格式**：1.0 的拒绝样本只解决"不强行指向"，1.5 的显式 None 进一步要求"逐请求明确应答存在性"——从隐式省略到显式拒绝，这个格式设计的演进对开放场景检测系统的接口设计很有启发
- **FP/GT 幻觉指标**：定位能力之外单独度量误报并用 GT 归一化，在 REC 评测里不常见，对无人机安全应用是关键指标
- **OPN 与主干解耦**：候选生成器可插拔，可以针对域（如低空遥感）换用专门的 proposal 网络
- **"先找到再数"的计数范式**：与 RemoteCount/DroneCount 的"图文相似度选数"完全不同，实例检测后聚合在密集场景更可靠，对 DroneCLIP 的计数评测设计是重要参照
- **两阶段训练防遗忘**：与 UAVIT-1M 的 instruction tuning 思路一致，但"通用数据混入 + 拒绝样本"配方值得抄

**实验设计亮点**: 1.5 的评测矩阵按"通用→无人机→具身空间→幻觉"分层组织，幻觉评测横跨 HumanRef（人类视角）、VisDrone/RefDrone（无人机视角），把"误报"从感知问题提升为安全指标。

## 疑问解答 (Q&A)

### Q1: 这是论文吗？数字可信吗？

**答**: 不是论文，也没有 arXiv 技术报告（README 无 citation 条目）——**官方博客就是其"论文"**。1.0 的核心数字（COCO 45.3 等）为官方正文陈述；1.5 的全部表格以图片形式发布，具体数值无法逐项核对，采用前需复现验证。

### Q2: 区域 token 方案的候选区域从哪来？漏检候选怎么办？

**答**: 来自 Step 1 的 OPN（可换其他检测器）。这意味着 VLX-Seek 的召回上限受候选生成器约束——候选器没提出的框，LLM 再强也无法引用。这是与直接生成坐标方案（上限不受候选约束）的本质 trade-off。README 证实此局限的现实影响：**内部训练的 OPN 因公司政策未开源**，开源仓库实际用轻量替代品 WeDetect-Base-Uni——复现性能时应预期候选质量低于官方报告配置。

### Q3: 关注这个项目最容易踩的坑是什么？

**答**: 三处版本/开源状态信息容易搞错：
1. 0.6B/3B 权重未开源，仓库仅发布 10B——网上流传的 `omlab/VLX-Seek-1.5-3B` 下载命令不可用
2. OPN 未开源，仓库实际用 WeDetect-Base-Uni 生成候选框
3. 数字要区分版本：COCO 45.3 等是 1.0-3B 的成绩；幻觉对比 FP/GT 18 是 1.5 的成绩；1.5 其余表格数字未公布文本版

### Q4: 1.0 与 1.5 的关系一句话概括？

**答**: 1.0 提出并验证范式（区域引用 + HFRE + 两阶段训练，通用基准上以小胜大），1.5 不改范式、只做工程化强化——数据扩到具身视角、模型分三档、推理提速、幻觉从"隐式拒答"升级为"显式 None 格式"。选型上：研究范式看 1.0 博客，实际部署直接用 1.5。

### Q5: 与 WinARDet 是什么关系？

**答**: 解决同一个病（MLLM 定位中坐标生成不可靠），但药方正交：WinARDet 保留坐标生成、修复长序列历史累积问题（压缩窗口自回归）；VLX-Seek 干脆取消坐标生成、改为候选区域引用。前者面向极密集单图生成（RSDense 200-2000 目标），后者面向端侧交互式指代任务——密集开放场景下两者甚至可以组合（区域引用天然规避 WinARDet 要解决的长坐标序列问题，但受候选数量上限约束）。

### Q6: 对 DroneCLIP/DroneGLIP 项目有什么启示？

**答**: (1) VisDrone/RefDrone 进入其幻觉评测，说明低空 REC 已是活跃评测域且**误报是核心痛点**，DroneGLIP 的评测设计应纳入 FP/GT 指标；(2) "区域引用 vs 坐标生成 vs 坐标并行解码"三条路线的对比，为工作二的架构选型提供了坐标系；(3) 显式 None 格式对低空场景（目标常缺席）直接可借鉴；(4) 其无人机场景痛点描述（极小目标、密集布局、倾斜视角）与 DroneCLIP 的动机完全同源，可互相印证。
